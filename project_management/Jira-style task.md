### Настройка API
Создание минимального проекта с использованием FastAPI.

## Описание
# Как пользователь:
Я хочу иметь готовый шаблон FastAPI проекта с настроенной структурой, чтобы быстро разрабатывать новые эндпоинты без повторной настройки инфраструктуры с нуля.

# Что сейчас не так:
- Проект не инициализирован
- Отсутствует базовая структура каталогов
- Нет документации API

# Ожидаемый результат:
- Создан минимальный FastAPI проект с готовой структурой
- Настроена документация Swagger
- Проект запускается локально и отвечает на запросы

## Критерии приемки
- Создан новый проект с установленным FastAPI и Uvicorn
- Организована структура каталогов:
    app/main.py — точка входа
    app/routers/ — роутеры по эндпоинтам
    app/services/ — бизнес-логика
- Реализован базовый эндпоинт GET /health с ответом {"status": "healthy"}
- Настроена документация Swagger UI по адресу /docs
- Добавлен файл .env для конфигурации (порт, режим отладки)
- Написан requirements.txt со всеми зависимостями
- Проект успешно запускается и обрабатывает запросы

### Добавление endpoint-ов;

## Описание
Текущее приложение не предоставляет базовых информационных endpoint-ов для мониторинга и получения служебной информации. Для обеспечения observability и упрощения деплоймента необходимо добавить стандартные endpoint-ы для health checks и получения версии приложения, а также служебный endpoint для просмотра файловой структуры проекта.

# Как пользователь:
Я как разработчик хочу иметь возможность проверять статус и получать базовую информацию о приложении, чтобы обеспечить мониторинг, упростить отладку и быстро проверять работоспособность сервиса.

# Что сейчас не так:
- Отсутствует endpoint для проверки работоспособности сервиса (health check)
- Нет возможности узнать текущую версию приложения без просмотра кода или логов
- При возникновении проблем сложно быстро определить, что сервис жив и отвечает на запросы
- Отсутствует служебный endpoint для быстрого просмотра файловой структуры

# Ожидаемый результат:
После реализации будут доступны три новых HTTP endpoint-а, которые позволят:
1. Проверять статус сервиса через GET /health
2. Получать информацию о версии через GET /version
3. Просматривать список файлов проекта через GET /files

Все endpoint-ы должны корректно обрабатывать запросы и возвращать ответы в формате JSON
## Критерии приемки
**Endpoint GET /health**
- Возвращает HTTP статус 200 OK
- Ответ содержит JSON: {"status": "healthy"}

**Endpoint GET /version**
- Возвращает HTTP статус 200 OK
- Ответ содержит JSON: {"version": "значение_из_переменной_VERSION"}
- Значение версии берется из переменной окружения VERSION
- Если переменная не задана, возвращать {"version": "1.0"}

**Endpoint GET /files**
- Возвращает HTTP статус 200 OK
- Ответ содержит JSON: {"files": ["список_файлов_и_папок"]}
- Должны быть исключены системные файлы (например, .git, __pycache__, *.pyc)

### Подготовка Docker-запуска.

## Описание
Для обеспечения воспроизводимости окружения, упрощения деплоймента и разработки необходимо настроить Docker-контейнеризацию приложения. Необходимо создать Dockerfile, docker-compose.yml и подготовить окружение для запуска приложения через Docker.

# Как пользователь:
Я как разработчик/DevOps инженер хочу запускать приложение через Docker с возможностью настройки через переменные окружения, чтобы обеспечить консистентность окружения на всех этапах разработки и упростить деплоймент.

# Что сейчас не так:
- Отсутствует Dockerfile для сборки образа приложения
- Нет docker-compose.yml для управления сервисами
- Приложение требует ручной установки зависимостей
- Отсутствует возможность легкого масштабирования и переключения между окружениями

# Ожидаемый результат:
После реализации будет создана Docker-инфраструктура, позволяющая:
1. Собирать Docker-образ приложения
2. Запускать приложение в контейнере с настраиваемыми параметрами
3. Управлять конфигурацией через переменные окружения

## Критерии приемки
**Dockerfile**
- Используется официальный Python образ (python:3.9-slim или новее)
- Установлены все зависимости из requirements.txt
- Код приложения скопирован в контейнер
- Рабочая директория установлена как /app
- Настроен порт (по умолчанию 8080) через переменную окружения
- Добавлены команды для запуска приложения

**docker-compose.yml**
- Сервис app с корректной конфигурацией сборки
- Проброс портов с хост-машины в контейнер (порт настраивается через переменную)
Переменные окружения:
    - VERSION - версия приложения (по умолчанию "1.0")
    - APP_PORT - порт приложения (по умолчанию 8080)
- Монтирование volumes для разработки (горячая перезагрузка)
- Использование кэширования слоев для ускорения сборки
