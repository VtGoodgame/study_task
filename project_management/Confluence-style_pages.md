### FastAPI Project Template
## Описание проекта

Проект представляет собой шаблон микросервиса на базе FastAPI с готовой инфраструктурой для быстрой разработки REST API. Включает настройку Docker, переменных окружения, структуру каталогов и базовые эндпоинты для мониторинга.

## Технологический стек

| Компонент | Технология |
|-----------|------------|
|Web-фреймворк|FastAPI|
|ASGI сервер|Uvicorn|
|Язык|Python|
|Контейнеризация|Docker|
|Оркестрация|Docker Compose|

## Структура проекта
```css
study_task/
├── app/                          # Основной код приложения
│   ├── __init__.py
│   ├── main.py                   # Точка входа FastAPI
├── requirements.txt              # Зависимости Python
│   ├── routers/                  # Маршруты API
│   │   ├── __init__.py
│   │   ├── health.py             # Health check endpoints
│   │   ├── version.py            # Version endpoint
│   │   └── files.py              # Files endpoint
│   └── services/                 # Бизнес-логика
│   │   ├── __init__.py
│   │   └── path.py       # Работа с файловой системой
├── .env.example                  # Шаблон переменных окружения
├── .env                          # Переменные окружения (не в git)
├── .gitignore                    # Игнорируемые файлы Git
├── .dockerignore                 # Игнорируемые файлы Docker
├── Dockerfile                    # Инструкции сборки образа
├── docker-compose.yml            # Оркестрация сервисовя
└── README.md                     # Документация
```
## Ключевые эндпоинты
| Метод | Эндпоинт | Описание |
|-------|----------|----------|
|GET|/|Приветственное сообщение|
|GET|/health|Проверка здоровья сервиса|
|GET|/version|Версия приложения|
|GET|/files|Список файлов проекта|
|GET|/docs|Swagger документация|
|GET|/redoc|ReDoc документация|

## Стратегия ветвления
Проект использует Git Flow с упрощенной структурой для быстрой разработки.
```css 
main (production)                    ← стабильная версия для продакшена
  ↑
develop (development)                ← интеграционная ветка разработки
  ↑
  ├── feature/название-функции       ← новые функции
  └── bugfix/название-ошибки         ← исправление ошибок
```

## Правила коммитов (Conventional Commits)
# Формат коммита
```css 
    <type>(<scope>): <subject>

    <body>

    <footer>
```

# Типы коммитов (Types)
| Тип | Описание | Пример |
|-----|----------|--------|
|feat|Новая функциональность|feat(api): добавил эндпоинт /files|
|fix|Исправление ошибки|fix(docker): исправил сборку образа|
|docs|Изменения в документации|docs(readme): обновил инструкции|
|style|Форматирование кода|style: привел код к PEP8|
|refactor|Рефакторинг|refactor(services): выделил бизнес-логику|
|test|Добавление/изменение тестов|test(health): добавил тесты для /health|
|ci|Настройка CI/CD|ci: добавил GitHub Actions|
|build|Изменения в сборке|build: обновил Dockerfile|
|revert|Откат изменений|revert: откатил коммит abc123|

# Области (Scopes)

|docs|Документация|
|tests|Тесты|
